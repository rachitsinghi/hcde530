C4 — APIs and Data Acquisition
Working with APIs shifted my understanding of data from something static to something that is actively structured, queried, and shaped through decisions. Instead of just “getting data,” I had to read documentation, identify the right endpoint, and understand how the API’s response schema translates into something usable. For example, when calling the Pexels Search API, I wasn’t just retrieving images, I was parsing a nested JSON response to extract specific fields like alt text, avg_color, and image URLs, and then deciding how to structure that into a CSV for downstream analysis . This forced me to think about data not as given, but as something that needs to be filtered, interpreted, and reshaped depending on the use case.

What became especially clear is that APIs don’t give you exactly what you need, they give you raw material. The real learning came from what I chose to do with that data. For instance, I extended the pipeline by downloading images from the returned URLs and then analyzing them for pill shape and color, combining text-based parsing with image-based heuristics when metadata was incomplete . This made me confront ambiguity in real-world data and design fallback strategies, which is very different from working with clean datasets. I also learned the importance of responsible API usage, managing API keys through environment variables instead of hardcoding them ensured my workflow was both secure and reproducible . Overall, this assignment moved me from “using data” to actually thinking like someone who acquires, evaluates, and operationalizes it.

Attempt 2 -
C4 — APIs and Data Acquisition
For this assignment I worked with two APIs and built a three-script pipeline that went well beyond a basic fetch-and-print. The first script, export_pexels_to_csv.py, called the Pexels Search API at https://api.pexels.com/v1/search with queries like "pharmacy stock photo" and "medicine flatlay white background," paginating through results using limit and offset parameters until I had at least 50 unique photos. From each JSON response I extracted twelve fields including id, avg_color, alt (the image caption), and nested image URLs from the src object, which required indexing two levels deep into the response rather than just reading top-level keys. API keys were loaded from a .env file using os.environ.get("PEXELS_API_KEY") and never written directly into the script, which also meant I could commit the code to GitHub without exposing credentials.

The second script, download_pexels_csv_images.py, took the exported CSV and downloaded the actual JPEG files from the CDN URLs returned by the first API call. This step was separate by design so I could re-run the analysis without hitting the API rate limit again. The third script, analyze_pexels_shape_color.py, was where the real data work happened. I used Pexels' alt text field as the primary source for classifying each image by pill shape (blister pack, oval capsule, scattered tablets, heart arrangement) and pill color, writing regex rules and keyword phrase lists to extract those categories from the caption text. When the caption did not name a color but clearly described pills, I fell back to analyzing the actual JPEG using Pillow, cropping the center 40% of the image and sampling pixel colors, converting RGB to HSV, and mapping hue and saturation values to human-readable color families like "orange" or "blue." The final output was a categorized CSV and a markdown summary grouping all 50 images by shape and color, with 10 distinct shape categories and 10 distinct color categories found across the dataset.

Two things stood out. First, the API response gave me far more than I asked for, and deciding which fields to keep and which to discard required understanding what downstream analysis I was going to do with the data, not just what the endpoint returned. Second, the fallback from caption text to pixel analysis taught me that real-world data rarely comes in one complete form. For a healthcare or HCD context where you might be categorizing pharmaceutical imagery at scale, building in multiple evidence sources and documenting which source was used per row (I tracked this in a pill_colour_source column) is what makes a pipeline trustworthy rather than just functional.
